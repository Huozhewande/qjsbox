# qjsbox

[中文说明](README.zh-CN.md)

Run untrusted JavaScript rules from Go, one sandboxed process per call.

qjsbox is for products that let operators or customers write small pieces of
logic — risk rules, scoring factors, routing conditions — and need to run them
on a server without trusting them. Each evaluation starts a fresh native worker
built from [QuickJS](https://bellard.org/quickjs/). The worker parses the
script, checks it against a closed syntax allow-list, runs it with frozen
intrinsics and no clock, randomness, modules, filesystem or network, and exits.
The Go side enforces deadlines, size limits and a hard concurrency cap.

```go
runner := qjsbox.New("/abs/path/to/qjsbox-worker") // share one Runner

res, err := runner.Execute(ctx, qjsbox.Request{
	Kind:              "RULE",
	Code:              `return factors.ordersLastDay >= 2 && input.user.verified === false;`,
	Input:             json.RawMessage(`{"user":{"verified":false}}`),
	AllowedReferences: []string{"ordersLastDay"},
}, func(ctx context.Context, ref string) (qjsbox.Value, error) {
	return qjsbox.Value{Type: "NUMBER", Value: json.RawMessage(`3`)}, nil
})
// res.Value == true, res.Reads == ["ordersLastDay"]
```

## Why another JavaScript sandbox

In-process interpreters such as goja or otto share your server's address space:
an interpreter bug or an unbounded allocation affects the whole service. qjsbox
puts every evaluation behind an OS process boundary instead and layers several
independent limits:

| Layer | What it does |
|-|-|
| Static analysis | Acorn AST walk rejects modules, `async`/generators, `with`, the implicit `arguments` object and dynamic `factors[...]` access before anything runs. |
| Language | Frozen globals and built-in prototypes; `Function`, `eval`, `Date` and `Math.random` removed; inputs are deep-frozen read-only proxies. |
| Engine | 64 MiB QuickJS heap ceiling, 512 KiB JS stack, interrupt hook on a 900 ms deadline. |
| Process | Fresh process per call, inherited descriptors closed, no core dumps, no file growth, 1 s CPU. |
| Linux (x86-64, AArch64) | Hard 256 MiB address space, `no_new_privs`, architecture-checked seccomp allow-list of 13 syscalls. Opening files, sockets, `fork` and `exec` are denied. |
| macOS | Deny-by-default Seatbelt profile plus a sampled 128 MiB RSS guard. |
| Supervisor | 1 s parent deadline, kill-and-reap, at most 8 concurrent workers per Runner (`SCRIPT_BUSY` instead of queueing). |

Other platforms fail closed: the worker refuses to run if its sandbox cannot
be installed.

## Features

- **Two kinds of script.** A `FACTOR` computes one `TEXT`, `NUMBER` (finite) or
  `BOOLEAN` value from read-only input. A `RULE` returns a boolean and may read
  named factors through `factors.name`.
- **Lazy, memoized factor reads.** Factors are resolved by your Go callback only
  when the script actually touches them, at most once per call. `OnReuse`
  reports cache hits so you can trace `EXECUTED`/`REUSED` reads in order.
- **Static references.** `Analyze` returns every factor a rule can read without
  executing it, so you can validate dependencies before saving a rule.
- **Three-valued helper for generated rules.** Visual rule builders can emit a
  closed `__rule` syntax in which a missing fact is *unavailable* rather than
  silently `false` (see below).
- **Fail-closed values.** A missing input property, an unknown factor or a
  mistyped factor value is fatal even if the script catches the exception.
- **Deterministic time.** `context.now` is the Unix milliseconds you pass in.
- **Structured errors** with stable codes and, for script errors, line and column.

## Getting started

Requirements: Go 1.22+, a C compiler, and Python 3 (used only at build time to
verify vendored sources and embed the JavaScript). The build uses no network.

```sh
make worker      # builds bin/qjsbox-worker
make selftest    # proves file, network and process creation are denied
make test        # go test -race, including the native sandbox proof
make example     # runs examples/basic
```

Ship `bin/qjsbox-worker` next to your service and pass its absolute path to
`qjsbox.New`. Build it on, or for, each target platform. The worker writes its
protocol to a pipe; it is meant to be started by the Go supervisor, not run
with stdout redirected to a file.

## Three-valued rules

Code generated by a visual editor can use `__rule.all`, `__rule.any` and
`__rule.test`. The helper syntax is closed: a single `return`, delayed arrow
children, literal operands.

```js
return __rule.all([
  () => __rule.test('user.country', 'IN', ['XX', 'YY']),
  () => __rule.any([
    () => __rule.test('risk.score', 'GTE', 80),
    () => __rule.test('user.flagged', 'EXISTS')
  ])
]);
```

- `unavailable AND false` is `false`; `unavailable OR true` is `true`; a final
  `unavailable` is an error, never a pass.
- Operators: `EQUALS`, `GTE`, `LTE`, `IN`, `ANY_MATCH`, `EXISTS` (boolean fact,
  no operand). Facts may also be `SET` (string array) values.
- If your resolver returns `AvailableOptions`, any `EQUALS` string, `IN` or
  `ANY_MATCH` choice outside that catalog makes the leaf unavailable. This lets
  rules saved against an old option list degrade safely.
- `Analyze` returns the literal `HelperTests`, so a server can validate the
  operator and operand choices of submitted code without executing it.

## Limits

| Limit | Value |
|-|-|
| Source | 64 KiB |
| Input | 1 MiB, nesting depth 64 |
| Declared references | 512, each up to 256 bytes |
| Factor read operations per call | 512 (including cache hits) |
| Output / factor value | 64 KiB |
| Deadline | 1 s in Go (startup, parsing, resolver waits, encoding); 900 ms in the worker |
| Concurrency | 8 workers per `Runner` |

## Error codes

| Code | Meaning |
|-|-|
| `SCRIPT_SYNTAX` | The script does not parse. |
| `SCRIPT_FORBIDDEN` | Modules, `async`, generators or `with`. |
| `SCRIPT_REFERENCE` | Dynamic or undeclared factor access, implicit `arguments`, invalid helper code. |
| `SCRIPT_INPUT_MISSING`, `SCRIPT_FACTOR_UNAVAILABLE`, `SCRIPT_REQUIRED_VALUE` | A required input or factor was absent, failed or had the wrong type. |
| `SCRIPT_TYPE` | Wrong return type. |
| `SCRIPT_ERROR` | An uncaught JavaScript exception. |
| `SCRIPT_TIMEOUT`, `SCRIPT_CANCELLED` | Deadline exceeded or context cancelled. |
| `SCRIPT_LIMIT` | A size, depth, read or memory limit was exceeded. |
| `SCRIPT_BUSY` | All worker slots of this Runner are in use. |
| `SCRIPT_KIND`, `SCRIPT_INPUT`, `INVALID_REQUEST` | Invalid request. |
| `SCRIPT_UNAVAILABLE`, `SCRIPT_PROTOCOL` | The worker could not start, its sandbox failed, or it broke the protocol. |

## Resolver contract

Your `ResolveFunc` and `OnReuse` callbacks are trusted host code. The resolver
runs synchronously while the worker waits, must pass the supplied context into
any nested work, and must return promptly when it is cancelled. `Execute` only
returns after the resolver has returned and the worker has been reaped, so a
timed-out call cannot keep mutating your state afterwards. `OnReuse` must only
record the event in memory.

## Platform notes

- The Linux guarantees are verified by running `make test` on Linux; a passing
  macOS run says nothing about the Linux sandbox. CI runs both.
- macOS refuses finite `RLIMIT_AS`/`RLIMIT_DATA` for unprivileged processes, so
  whole-process memory there is bounded by the QuickJS heap ceiling plus a
  10 ms RSS sampler. **The sampler can overshoot; it is not a hard OS limit.**
  Use Linux for production.
- `sandbox_init` is deprecated on macOS but remains the only unprivileged way
  to apply a Seatbelt profile to the current process.

See [worker/README.md](worker/README.md) for the native protocol and the
provenance of the vendored sources.

## Status

qjsbox is a small, focused library extracted from an internal rule-authoring
system, where it backs factor tests, rule tests and scenario simulation. It is
pre-1.0: the Go API may still change. It is not a rules engine — storage,
versioning and rule orchestration are left to you.
